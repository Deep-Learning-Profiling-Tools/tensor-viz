The `tools/` directory contains repository maintenance scripts, not runtime library code.

`sync-demo-assets.mjs` runs after the demo build. It copies Vite's generated files into `python/src/tensor_viz/static/` so the Python package serves the same frontend that local development tested.

`sync-linear-layout-examples.py` keeps baked linear-layout demo tabs synchronized with the LL-viz Python demo source when that source is available. It rewrites only the marked generated block in the linear-layout extension, which keeps hand-written TypeScript separate from generated examples.

Tooling here should stay deterministic and small. If a script starts needing app state or viewer internals, move that behavior into the package that owns the concept and let the tool call the package-level API.

`check-ts-docs.mjs` is the mechanical guard for the TypeScript commenting rules in `AGENTS.md`. It parses source files with the TypeScript AST, not regular expressions, so declarations are checked as declarations: functions, function-valued variables, classes, interfaces, type aliases, enums, and methods. In normal mode, it audits every first-party TypeScript source file. With explicit file or directory arguments, it audits only those paths. In `--staged` mode, it audits every staged TypeScript source file as a whole file, which means touching a file also makes that file's existing undocumented helpers visible.

The checker enforces the AGENTS.md function-docstring contract by default. Function-like declarations must have a prose summary, `@param` entries for every parameter, `@returns` for every non-constructor/non-setter function, either `@throws` or `@noThrows`, and `@example`. Direct `throw` statements require `@throws`; `@noThrows` documents that the function has no direct throw path in its own body. Type-level declarations such as interfaces and type aliases must also include examples. The `--relaxed-jsdoc` flag is only for debugging the checker itself, not for publish gates.

The same checker enforces two non-docstring rules. First, source files must meet a configurable comment-line ratio, currently 10 percent. Second, tiny non-exported top-level helper functions must have at least three local references. A tiny helper with fewer call sites is usually a sectioning helper, not a real abstraction; interface-boundary exceptions can be marked with a JSDoc `@interfaceBoundary` tag. Larger algorithmic routines are still checked through JSDoc and comment density instead of being forced inline.

The full `npm run check:ts-docs` command is intentionally broad and should stay green before publishing. The staged command is the publish-friendly incremental gate: it prevents commits from changing a TypeScript source file while leaving that same file below the documented standard. For targeted cleanup, run `node tools/check-ts-docs.mjs packages/viewer-demo/src/app-entry.ts` or pass any other file/directory path.

`check-ts-docs-llm.mjs` is the semantic companion to the mechanical checker. It asks an LLM to judge whether existing JSDoc text is actually useful: summaries should explain feature behavior, parameters should name concrete input shapes, returns should explain how callers use the value, throws/noThrows should name real failure modes, and examples should use realistic values instead of placeholders. The LLM output is structured around per-symbol `issues` and `replacements`, so a reviewer can replace only the adjacent JSDoc for the matching declaration instead of copying a large blob by hand.

The default LLM mode is pre-commit friendly: `npm run check:ts-docs:llm` audits staged TypeScript files only when their working-tree copy has no extra unstaged edits. `npm run check:ts-docs:llm -- --staged` audits every staged TypeScript blob from the git index, even when the working tree has moved on. `npm run check:ts-docs:llm -- --all` audits the whole first-party TypeScript source tree. `npm run check:ts-docs:llm -- --diff --base=origin/main` audits files changed relative to the merge-base with the chosen branch. Use `--print-prompt` to inspect prompts without spending API tokens, `--symbol=<name>` to focus one declaration, and `--include-direct-helpers` to audit helpers called by that declaration in the same file.
